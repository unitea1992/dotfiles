# Orca のワーカーを回すときの決まり

どのリポジトリでも、`orca orchestration` でワーカーを起こす・回すときに当てる。リポジトリ固有の手順は、そのリポジトリの規則に書く。モデルと effort の配分は `pstack-models.md` に従う。

- **端末は完了の約2分後に閉じる。** 後から話しかけたいワーカーだけ、`worker-start --keep-open`（起動後なら `worker-keep-open`）で残す。新しい worktree（`new-child`・`new-top-level`）で起こしたワーカーは開いたままになるので、使い終えたら `worker-release` で閉じる。
- **出力は `worker-read --source auto` で読む。** 端末の無いワーカーがあり、`--source terminal` は拒否される。`orca chat list/read/send/wait` は 1.4.258 で取り消されていて使えない。
- **起動の失敗は `--retry-of` で再試行する。** Linux で `agent_not_in_foreground` の初回失敗が報告されている。`--retry-of` は `--task` に失敗した Task を指す必要があり、配置を引き継がない。`--on`・`--worktree`・`--agent`（または `--terminal`）を同じに指定し直す。
- **権限の承認（コーディネーターの承認はオン）。** コーディネーターは、ワーカーの許可確認に理由を添えて答えられる。渡した作業の範囲内の許可は、止めずに通す（確認を増やさない）。許可しないのは、作業と関係のないパスや資源への要求。オーナーに回す条件は、そのリポジトリの規則に従う（決まりが無ければ、料金が出る操作・外部サービスの新規登録・本番のデータや資源の削除だけ）。
- **作業場所は Workspace Cleanup が消す。** マージ済みの作業場所は1時間おきに消える（pin、未コミット、未 push、稼働中は残る）。調査の証拠など残したい作業場所は、先に pin する。取り込み前に未マージの変更が無いかを確かめる決まりは、今までどおり。
